# Task 5.2 — Claim Verifier Performance Optimization & Contradiction Reasoning

## What I built
- **Fast-path PDF text extraction**: Swapped `extract_docling` for `extract_pdf` (PyMuPDF) as the primary text extraction step in `shield.py`. PyMuPDF completes in ~40ms offline without triggering remote Hugging Face Hub checks or multi-minute RapidOCR CPU pipelines. Retained Docling as an automatic fallback for image-only/scanned PDFs.
- **Batch claim embeddings**: Integrated `embed_batch` in `verifier.py` to embed all extracted claims in a single forward pass per collection instead of running individual sequential vector inferences.
- **CrossEncoder reranker candidate tuning**: Reduced vector candidate retrieval from `top_k=10` to `top_k=5` per collection, halving CPU inference load during MiniLM cross-encoder reranking.
- **Verbatim quote fast-path**: Added direct substring matching (`best_score >= 0.80 and any(claim.lower() in t.lower() for t in evidence_texts)`) that bypasses LLM inference for direct quote citations.
- **Controlled LLM generation parameters**: Added `num_predict` and `num_ctx` parameters to `generate()` in `ollama_client.py` (preserving defaults for RAG query/chat). Ambiguous claims query Ollama with `num_predict=60` and `num_ctx=1024` for quick ~1s verdicts.
- **Contradiction reasoning & discrepancy descriptions**: Enhanced `_llm_support_or_contradict` prompt to return both verdict and a 1-sentence description explaining why a claim conflicts with records (`REASON:`). Saved this explanation into SQLite database `shield_reports` records.
- **Substantive claim filtering**: Filtered short noise fragments (<15 chars) and capped claim verification to the top 25 substantive claims to ensure reliable completion within 30–50s on local laptop hardware.
- **UI breakdown**: Updated `frontend/index.html` to display the specific discrepancy reason and cited record excerpt for contradicted claims, plus detailed descriptions for unverified statements.

## Known gaps / deviations
- Scanned/image-only PDFs still invoke Docling OCR when PyMuPDF detects no selectable text; on low-spec hardware without GPU acceleration, OCR may take longer than digital PDFs.
