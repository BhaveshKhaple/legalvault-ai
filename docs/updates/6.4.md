# Task 6.4 — Auth + JWT + multi-tenancy

## What I built

- `backend/app/auth/` package: password hashing (argon2id), JWT encode/decode
  (HS256, 12h TTL), FastAPI dependencies (`get_current_user`, `require_role`,
  `get_case_for_user`), and pydantic schemas.
- `/v1/auth/register` — public. First user in the DB is promoted to admin;
  subsequent self-signups are analysts. Returns JWT.
- `/v1/auth/login` — email + password → JWT. Wrong-password and unknown-email
  both return the same 401 (no user-enumeration leak).
- `/v1/auth/me` — returns the caller's identity from their Bearer token.
- **Role hierarchy** (higher includes lower): admin > analyst > viewer.
  Analyst+ can create/delete cases and upload/query/shield; viewer is read-only.
- **Multi-tenancy** on cases: `Case.created_by` is stamped on create. Non-admins
  see only their own cases; admin sees everything. Cross-tenant fetches return
  404 (not 403) so we never leak that another user's case exists.
- Existing routers (cases, documents, query, shield) now go through
  `get_case_for_user()` for every case-scoped route.

## Known gaps

- Legacy cases (created before 6.4 with `created_by=NULL`) are visible to admin
  only. Analysts cannot see them. Bhavesh may want a one-shot backfill script
  to assign them to a specific user before turning off admin bypass.
- No token refresh endpoint yet. TTL is 12h — users log in again after expiry.
- No admin route to change another user's role. Downgrade to viewer or promote
  to admin requires a DB write. Add `/v1/users` admin endpoints later if needed.
- No rate limiting on `/register` or `/login`. `RATE_LIMIT_PER_USER_PER_MIN` is
  in `.env.example` but nothing consumes it yet — that's a separate TRD §12.5
  task.
- JWT secret in dev `.env` is a placeholder. Rotate before staging/prod:
  `python -c "import secrets; print(secrets.token_hex(32))"`
